### Q1：访问一个链接时，怎么确定落到 Index 这个 Action 上？

**答：**

- 路由写在 `App_Start/RouteConfig.cs`，模板是 `{controller}/{action}/{id}`；

- `defaults` 里设了 `action = "Index"`，所以 URL 只写控制器不写动作时，自动填 Index；

- 因此 `/User` 与 `/User/Index` 完全等价，Index 是默认值决定的，不是硬编码；

- 匹配还要满足命名约定：类名必须 `XXXController`，URL 里只写 `XXX`

### Q2：学过 SqlHelper + DAL + BLL，怎么直接改造到 Repository/Service 这套？

**答：** 完成了一次完整重构，对应关系是：

|            |            |                                        |
| ---------- | ---------- | -------------------------------------- |
| 老架构     | 新架构     | 职责                                   |
| SqlHelper  | DbContext  | 数据库操作入口                         |
| DAL        | Repository | 只做数据存取，不写业务、不写事务       |
| BLL        | Service    | 业务校验、事务、多仓储编排，不直接查库 |
| Controller | Controller | 只调 Service，不碰 DbContext           |

落地动作：建实体与 DbContext → `Database.SetInitializer(null)` 关闭自动建库 → 抽 `IUserRepository` 接口与实现 → 抽 `IUserService` 并注入仓储与上下文 → Controller 只依赖接口。Controller 里看不到任何 EF 代码。

### Q3：为什么要改成 Repository 和 Service？

**答：** 解决老三层的实际毛病：

- 老 DAL 把 SQL 写死，强依赖数据库，换 ORM 要动多处；

- 老 BLL 边界容易失控，经常直接在业务层写 SQL，查询和业务混在一起；

- 这两点导致业务逻辑无法脱离数据库测试；

- Repository 面向"实体对象"而不是"表/SQL"，把数据来源抽象掉；

- Service 统一收口业务规则与事务，多个仓储组合在一个上下文里提交；

- 接口抽象后，换 Dapper 只需换注册，Service 一行不改。

### Q4：`_db.Users.Add(user)` 和 `_db.SaveChanges()` 有什么区别？

**答：**

- `Add` 只是把对象加入上下文跟踪缓存，标记 `EntityState.Added`，**不发 SQL，数据库无变化**，可以连 Add 好几个；

- `SaveChanges` 才遍历所有非 Unchanged 实体，批量生成 INSERT/UPDATE/DELETE，在一个事务里执行，返回影响行数，之后状态回置 Unchanged；

- 类比老写法：`Add` ≈ 组装好 SqlCommand 还没执行，`SaveChanges` ≈ 调用 `ExecuteNonQuery`；

- 三个连带结论：忘记 SaveChanges 数据不入库；多次 SaveChanges 是多次独立事务，失去原子性；多个 Add 后只调一次才是单次往返、单个事务；

- 这就是把 SaveChanges 放在 Service 而不是 Repository 的根本原因。

### Q5：怎么引入 Autofac，让 Controller 不再手动 new？

**答：** 四步走：

1. 装 `Autofac` + `Autofac.Mvc5`；

2. 建 `App_Start/AutofacConfig.cs`：`RegisterControllers` 扫控制器、注册 DbContext（**InstancePerRequest**）、注册 Repository 与 Service 的接口映射、`builder.Build()`、`DependencyResolver.SetResolver`；

3. `Global.asax` 的 `Application_Start` 调用注册；

4. Controller 改成构造函数注入 `IUserService`，删掉所有 new。

关键点：DbContext 必须 `InstancePerRequest`，一次请求共用一个上下文，事务语义才成立；写成 `InstancePerDependency` 会导致每个注入点都是新上下文，事务失效。Autofac 会递归装配整条依赖链，不用我们写任何 new。

### Q7：全局异常、自定义错误页、log4net、单元测试这一套怎么落地？

**答：** 分四块，全部实操跑通。

**① 全局异常 + 错误页**

- 自建 `GlobalExceptionFilter : IExceptionFilter`，在 `OnException` 里：置 `ExceptionHandled = true` 阻断黄页 → 写日志 → 判断是否 AJAX → AJAX 返回统一 JSON，普通请求返回 Error 视图带 ErrMsg；

- `FilterConfig` 里注册它，替换原生 `HandleErrorAttribute`；

- `Web.config` 配 `customErrors mode="RemoteOnly"`，`defaultRedirect` 指共享 Error 页，单独配 404；

- 实测：Service 里 throw 异常，页面不再出黄页，日志文件成功落地。

**② log4net**

- `configSections` 里注册 section handler → 配 `RollingFileAppender`（按日期滚动到 `Logs/log.txt`）与 root 级别 → `AssemblyInfo.cs` 加 `XmlConfigurator(Watch = true)` 自动加载 → 封装 `LogHelper` 静态类 → 在异常过滤器中调用。

**③ 配置管理**

- `ConfigurationManager.AppSettings` 读 `Web.config` 的 appSettings；

- `Web.Debug/Release.config` 做发布时转换，替换连接串；

- 和 Core 的 `appsettings.json` + 环境变量体系做了对比。

**④ 单元测试**

- 项目引用主项目，装 `MSTest.TestFramework` + `MSTest.TestAdapter` + `Moq`；

- `Mock<IUserRepository>` 设 `Exists("test")` 返回 true，构造 `UserService`，断言新增返回 false；再补一条不重复返回 true 的正向用例；

- 全程不连数据库、不启 EF，只验证业务规则；

### Q8：customErrors 是什么？

**答：** [ASP.NET](http://ASP.NET) 老框架内置的错误处理开关，写在 `<system.web>` 下，控制出错时给不给看黄页、跳不跳自定义页。

- `mode="Off"` 全看黄页（调试用）；`On` 全走自定义页；`**RemoteOnly**` **最推荐**（本地看黄页排错、外部看友好页）；

- `defaultRedirect` 兜住没单独配置的错误码，`<error statusCode="404">` 单独指路。

和异常过滤器的分工：

- `IExceptionFilter` 只抓 Action 内部抛出的异常，能区分 AJAX、能写日志；

- `customErrors` 兜住过滤器管不到的：路由不存在、静态资源 404、未进 MVC 管道的错误；

- 补充：customErrors 是 302 跳转，状态码会变 200，真要返回 404/500 得用 `system.webServer/httpErrors`。

### Q10：前后端交互这套（AJAX / RESTful / async）怎么学？

**答：** 三步：

1. **AJAX + Json()**：Controller 返回 `Json(ResultModel)` 不返回 View，前端按 `res.Code` 分支处理；统一返回模型 Code/Msg/Data，和全局异常返回的 JSON 结构对齐，前端一套逻辑通吃；

2. **Web API / RESTful**：MVC 可返回视图也可返回 JSON，Web API 只返回数据；REST 用 GET/POST/PUT/DELETE 表达增删改查，URL 面向资源（`/api/user/1`）而不是动作（`/User/AddUser`）；ApiController + `IHttpActionResult` + `Ok()`，过滤器与 DI 思路和 MVC 相通；

3. **async/await**：IO 密集才用异步，EF 侧 `AnyAsync / FirstOrDefaultAsync / SaveChangesAsync`；Action 返回 `Task<ActionResult>`；铁律是全链路 async/await，禁止 `.Result` 和 `.Wait()`（Framework 下极易死锁）；Moq 用 `ReturnsAsync`。
