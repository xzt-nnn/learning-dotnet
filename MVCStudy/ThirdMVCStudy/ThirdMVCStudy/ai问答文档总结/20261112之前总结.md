### Q1：访问一个链接时，怎么确定落到 Index 这个 Action 上？

**答：**

- 路由写在 App_Start/RouteConfig.cs，模板是 {controller}/{action}/{id}；

- defaults 里设了 action = "Index"，URL 只写控制器不写动作时自动补 Index；

- 因此 /User 与 /User/Index 完全等价，Index 是默认值决定的，不是硬编码；

- 匹配还要满足命名约定：类名必须是 XXXController，URL 里只写 XXX。

### Q2：ViewData、ViewBag、TempData 怎么选？

**答：**

|          |                              |                          |                              |
| -------- | ---------------------------- | ------------------------ | ---------------------------- |
| 载体     | 类型                         | 存活范围                 | 适用场景                     |
| ViewData | ViewDataDictionary           | 当前请求                 | 取值要强转，已少用           |
| ViewBag  | dynamic（本质包装 ViewData） | 当前请求                 | 同请求内控制器到视图，最常用 |
| TempData | 走 Session                   | 跨一次请求，读一次即失效 | 重定向后再提示消息           |

结论：同请求传值用 ViewBag，提交后跳转再提示用 TempData。

### Q3：Layout、Partial、@section 各解决什么？

**答：**

- Layout 是母版页，_ViewStart.cshtml 统一挂载，避免每页重复页头页脚；

- Partial 是分部视图，复用片段（列表项、页头、表格行）；

- @section 配合 RenderSection，让个别页面往固定区块塞脚本或侧栏内容；

### Q4：过滤器有哪几种，各自管什么？

**答：** 一句话理解：在 Action 执行的前后、视图渲染的前后、发生异常时自动插入一段代码，不用每个 Action 重复写。

MVC5 一共四种内置过滤器，对应四个执行时机（面试必背）：

|            |                      |                                       |                               |
| ---------- | -------------------- | ------------------------------------- | ----------------------------- |
| 过滤器类型 | 接口                 | 执行时机                              | 典型用途                      |
| 授权过滤器 | IAuthorizationFilter | 最早，Action 未执行，甚至模型绑定之前 | 登录、权限校验（[Authorize]） |
| 动作过滤器 | IActionFilter        | Action 执行前、Action 执行后          | 日志、参数校验、计时          |
| 结果过滤器 | IResultFilter        | View 渲染前、渲染后                   | 统一响应头、压缩、计时收尾    |
| 异常过滤器 | IExceptionFilter     | Action 或视图渲染抛出异常时           | 统一错误出口、写日志          |

- 完整执行顺序：授权 → 动作过滤器前 → Action → 动作过滤器后 → 结果过滤器前 → 视图渲染 → 结果过滤器后。异常过滤器只在出错时才接管，位置在异常发生点之后；

- 开发方式：继承 ActionFilterAttribute，重写 OnActionExecuting（Action 前）与 OnActionExecuted（Action 后）。继承一次同时拿到"动作"和"结果"两个时机，实际项目里最常用这一种；

- 注册层级：全局 GlobalFilters.Filters.Add → 控制器 → Action，越靠近 Action 优先级越高，同级再按 Order 排序；

- 授权过滤器要点：重写 OnAuthorization，校验失败时直接给 filterContext.Result 短路返回，Action 不再执行，这就是登录拦截的实现原理；

- 三个常见坑：一，授权过滤器里不能假设模型已绑定，它跑在绑定之前；二，OnActionExecuting 里可以读 ModelState 做统一参数校验；三，OnActionExecuted 里别改已经提交的 Response，会报"响应头已发送"；

- 和 AOP、中间件的区别：过滤器是 MVC 管道内的钩子，只覆盖进了 MVC 的请求；中间件更靠前、更通用；WebApi 的过滤器属于 System.Web.Http 命名空间，自成一套，**不能和 MVC 过滤器混用**。

典型落地：[Authorize] 管登录、自定义 MyActionFilter 记日志与耗时、GlobalExceptionFilter 做统一异常与错误页。

### Q5：模型校验为什么前端校验不够？

**答：**

- 前端校验是体验层，F12 就能删掉或改参数绕过；

- 后端 ModelState.IsValid 才是安全底线，DataAnnotations（[Required]、[StringLength]、[Range]）在服务端再校验一遍；

- 校验失败返回 View(model) 保留用户输入，通过才执行业务。

### Q6：CSRF 的原理是什么？

**答：**

- 用户登录 A 站，浏览器存了 Cookie；

- 再访问恶意 B 站，B 站偷偷向 A 站发 POST；

- 同源策略不拦"发送"，浏览器**自动带上 A 站 Cookie**，服务端以为是本人操作；

- 本质是借用了浏览器对 Cookie 的自动携带，攻击者不需要密码也不需要登录态。

### Q7：MVC 怎么防？为什么这样就防住了？

**答：**

- 视图写 @Html.AntiForgeryToken()，Action 加 [ValidateAntiForgeryToken]；

- Token 同时存在页面隐藏域和同名 Cookie 中，提交时必须两处一致；

- 恶意站点能利用 Cookie，但**读不到隐藏域里的 Token**（同源策略禁止跨域读页面内容），伪造请求必然缺字段；

- 补充：SameSite Cookie 是浏览器层的同类防护，可与 Token 叠加。

### Q9：XSS 分几类，Razor 哪里会破防？

**答：**

- 反射型：代码在 URL 参数里，点开即触发，不落库；

- 存储型：代码入库，所有访问者都中招，危害最大；

- DOM 型：后端完全不参与，前端 JS 读 URL 参数写进 DOM，Razor 的 @ 转义对它无效；

- @变量 输出自动 HTML 编码，@Html.Raw() 主动关掉转义，是漏洞源头，只有完全可信的富文本才允许用。

### Q10：为什么只弹个 alert，感受不到危害？

**答：**

- alert 只是"漏洞验证信号灯"，证明 JS 已经在你的页面里执行；

- 真实危害有四类：一，document.cookie 外传实现免密登录；二，用 innerHTML 把整页替换成高仿登录框钓鱼，**域名和证书都正常**；三，静默发 POST 改密码改资料；四，直接读页面明文把手机号订单信息外传；

- 真实攻击脚本不会弹窗，用户全程无感。

### Q11：HttpOnly、textContent、CSP 分别防什么？

**答：**

- HttpOnly：禁止前端 JS 读取该 Cookie，浏览器仍自动携带。只降低窃取登录凭证的风险，**不能防 XSS 本身**，篡改页面、钓鱼照样能做；

- textContent：只当纯文本写入，不解析标签，天然免疫 DOM 型 XSS；innerHTML 会执行 <img src=x onerror=...>；

- CSP：响应头 Content-Security-Policy 白名单限制脚本来源，default-src 'self' 后外域与内联脚本都被禁。

### Q12：上传漏洞的根源和加固顺序？

**答：**

- 根源是两件事同时成立：**上传目录允许执行脚本** ＋ **文件校验缺失**。传 hack.aspx 再访问，代码就在服务器跑了；

- 五个步骤：一，后缀白名单（黑名单绕不完）；二，Guid.NewGuid() 重命名，防 hack.aspx;.jpg 解析绕过与 %00 截断；三，校验文件头识别伪装；四，限制大小；五，上传目录 web.config 里 <handlers><clear/> 只留 StaticFile，让目录彻底失去执行能力做兜底。

### Q13：垂直越权和水平越权怎么区分？

**答：**

- 垂直越权是"功能权限"越级，普通用户打开管理员后台，靠角色校验拦；

- 水平越权是"数据权限"越界，同权限用户互相访问数据（改 URL 里的 id 看别人订单），靠数据归属校验拦；

- 水平越权最容易漏，因为很多项目只做了登录校验。修复必须从 Session 取登录人 ID（可信来源），叠加 o.Id == id && o.UserId == loginUserId，前端传的 id 永远不可信。

### Q14：SQL 注入怎么处理？

**答：**

- SQL 注入：全线参数化不拼字符串，参数化让输入永远当数据处理，无法改变语句结构。
