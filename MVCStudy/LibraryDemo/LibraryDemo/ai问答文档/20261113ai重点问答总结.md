## 1.LibraryContext 的OnModelCreating(DbModelBuilder modelBuilder)的DbModelBuilder 的作用是什么？



DbModelBuilder` 是 EF6 里专门用来“描述模型”的 构建器对象 （命名空间`System.Data.Entity` ）。

拆开名字就懂了：`Db` （数据库）+`Model` （模型）+`Builder` （构建器）。它本身不连数据库、不执行查询，只是一个 用来配置实体和表怎么映射的工具 。



你 new LibraryContext() 
        ↓
EF 首次构建模型时，自动调用 OnModelCreating(modelBuilder)
        ↓
你在里面通过 DbModelBuilder 描述：Book 和 Category 什么关系、表名是什么……
        ↓
EF 把描述结果编译成内存中的“模型（Model）”
        ↓
之后所有 LINQ 查询都基于这个模型翻译成 SQL



## 2.Autofac的注册方法有哪些

```csharp
container.Resolve<BookService>();    //  可以
container.Resolve<IBookService>();   // 找不到
```

而控制器构造函数要的是接口 `IBookService`，自然报 `Cannot resolve parameter`。

Autofac 的三种注册方式区别：

| 写法                           | 能解析什么                     |
| ------------------------------ | ------------------------------ |
| `.AsSelf()`                    | 只能 `Resolve<BookService>()`  |
| `.As<IBookService>()`          | 只能 `Resolve<IBookService>()` |
| `.AsImplementedInterfaces()`   | 自动注册它实现的所有接口       |
| `.AsSelf().As<IBookService>()` | 两种都能解析                   |

你现在的 [AutofacConfig.cs](file:///d:/平时测试使用/MVCStudy/LibraryDemo/LibraryDemo/App_Start/AutofacConfig.cs#L27-L30) 已经改成 `.As<IBookService>()`。以后加 `BorrowService` 时同理，注册成 `.As<IBorrowService>()`，别再用 `AsSelf()`。

另外提醒一句：`LibraryContext` 用 `AsSelf()` 是对的，因为 `BookService` 的构造函数要的就是具体类型 `LibraryContext`；如果以后想按 `DbContext` 注入，再改成 `.As<DbContext>()`。

## 4.解释下NLog的配置文件

这是 **NLog 的配置文件（NLog.config）**，NLog 是 .NET Framework（MVC5 里非常常用）的日志组件，用来记录程序日志，替代原生的 `Console.WriteLine`。
整体作用：**日志同时输出到两个地方：VS调试窗口 + 本地日志文件，不同级别分开控制**。

```
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="[http://www.nlog-project.org/schemas/NLog.xsd](http://www.nlog-project.org/schemas/NLog.xsd)"
      xmlns:xsi="[http://www.w3.org/2001/XMLSchema-instance](http://www.w3.org/2001/XMLSchema-instance)"
      autoReload="true"
      throwConfigExceptions="true">

  <targets>
    <!-- 文件日志 -->
    <target xsi:type="File" name="file"
            fileName="${basedir}/logs/${shortdate}.log"
            layout="${longdate}|${level:uppercase=true}|${logger}|${message}|${exception:format=tostring}" />

    <!-- 调试窗口 -->
    <target xsi:type="Debugger" name="debugger"
            layout="${longdate}|${level:uppercase=true}|${message}" />
  </targets>

  <rules>
    <logger name="*" minlevel="Debug" writeTo="debugger" />
    <logger name="*" minlevel="Info"  writeTo="file" />
  </rules>
</nlog>
```

## 外层 nlog 节点属性

2. `autoReload="true"`
   配置文件修改后，**不用重启网站，NLog自动加载新配置**，调试很方便。
4. `throwConfigExceptions="true"`
   NLog配置写错的时候，直接抛出异常，方便你排查配置错误；生产环境有时候会关掉。

## <targets>：日志输出目标（日志写到哪里）

target 就是目的地，这里定义了两个目标：`file` 和 `debugger`

### ① File 目标（写到本地文件）

```
<target xsi:type="File" name="file"
        fileName="${basedir}/logs/${shortdate}.log"
        layout="${longdate}|${level:uppercase=true}|${logger}|${message}|${exception:format=tostring}" />
```

- `xsi:type="File"`：类型是文件输出

- `name="file"`：这个target的名字，后面rules里通过名字引用

- `fileName="${basedir}/logs/${shortdate}.log"`

  - `${basedir}`：程序运行目录（bin目录下）
  - `${shortdate}`：当天日期 `2026-11-13`
    效果：按天分割日志，每天生成一个 log 文件，比如 `logs/2026-11-13.log`

- `layout` 定义**一行日志长什么样**，分隔符用 `|`

  - `${longdate}`：完整时间 `2026-11-13 16:30:22.1234`
  - `${level:uppercase=true}`：日志级别大写：INFO / DEBUG / ERROR
  - `${logger}`：日志对象名称（一般是类名）
  - `${message}`：你代码里写的日志消息
  - `${exception:format=tostring}`：如果有异常，把异常堆栈信息打印出来（非常重要，排错用）

示例生成的一行日志：

```
2026-11-13 16:30:22.1234|INFO|UserController|导出用户列表成功|
```

### ② Debugger 目标（输出到VS调试输出窗口）

```
<target xsi:type="Debugger" name="debugger"
        layout="${longdate}|${level:uppercase=true}|${message}" />
```

- `xsi:type="Debugger"`：输出到 Visual Studio 的【输出-调试】窗口
- layout 简单一点，没有logger和异常信息

## <rules>：日志路由规则（哪些日志往哪个目标写）

```
<logger name="*" minlevel="Debug" writeTo="debugger" />
<logger name="*" minlevel="Info"  writeTo="file" />
```

- `name="*"`：匹配所有类的日志（可以写 `UserController` 只匹配某个控制器）
- `minlevel`：**最低级别**，大于等于这个级别都会生效
  日志级别从小到大：`Debug < Info < Warn < Error < Fatal`
- `writeTo="xxx"`：指定使用上面定义好的target

    这条规则翻译：

2. 所有 ≥ Debug 的日志 → 输出到VS调试窗口（Debug、Info、Warn、Error、Fatal都会在调试窗口看到）
4. 所有 ≥ Info 的日志 → 写入日志文件（Debug日志**不会写入文件**！只有Info及以上才落盘）

>  重点坑：Debug日志只在VS调试窗口显示，不会保存到日志文件。

## 7.var query = _db.Books.Include(b => b.Category).AsNoTracking().AsQueryable()的Include()是干啥的

预加载（Eager Loading） 。它会生成`JOIN` ，把每本书对应的`Category` 一起查出来，装进`Book.Category` 属性。

不写的话也能拿到`b.Category` ，但每访问一次就会单独发一条 SQL（ N+1 查询问题 ）：列表里有 20 本书就多 20 条查询。`Include` 一次 JOIN 解决。

SELECT ... FROM [dbo].[Book] AS [Extent1]
INNER JOIN [dbo].[Category] AS [Extent2] ON [Extent1].[CategoryId] = [Extent2].[Id]
